# Хэндофф для новой сессии

Если ты читаешь это в свежей сессии Claude Code, запущенной прямо в этой
папке — вот что нужно знать, чтобы продолжить без потери контекста.

## Что это

Учебный мини-стенд для одного занятия (1–1.5 часа) по Kafka + CI/CD для
живой когорты QA-студентов. Полностью самостоятельный проект, не связан с
продуктовым TaskFlow-курсом.

## Что уже согласовано и сделано

Дизайн полностью проработан в брейнсторминге и зафиксирован в двух файлах
— это основной источник правды, читать их первыми:

- [`docs/DESIGN.md`](docs/DESIGN.md) — техническая спека: сервисы
  (`order-api` продюсер + `delivery-worker` консьюмер), 4 ручки, инфра
  (Kafka KRaft + Kafka UI + Postgres + ELK), 4 заложенных бага (2 на
  продюсере простые + 1 сложный батч-баг + 1 на консьюмере), git/CI-CD
  структура (`main` + 2 фиче-ветки, PR-триггер в GitHub Actions, зелёный
  CI несмотря на баги), сид БД, доступ через туннель.
- [`docs/LESSON_PLAN.md`](docs/LESSON_PLAN.md) — план занятия для
  ведущего: теория (Kafka + CI/CD), чек-лист диагностики по каждому багу,
  команды, плейбук «фикс → ретест» для обеих веток, тайминг на 90 минут.

Оба файла закоммичены (`3660952`). Реализация по ним завершена и
проверена: код `order-api` и `delivery-worker`, `docker-compose.yml`
(Kafka KRaft + Kafka UI + Postgres + ELK), seed-скрипт БД, GitHub
Actions workflow (lint+test на PR для обоих сервисов), а также ветки
`feature/producer-bugs` (3 бага + fix-коммит) и `feature/consumer-bug`
(1 баг + fix-коммит) — всё на месте и рабочее.

## Что дальше

Финальный ревью всей ветки `main` пройден, замечания устранены
(healthcheck/restart-policy в docker-compose, синхронизация README/
HANDOFF со статусом, документация ограничений `/admin/reset`,
логирование consumer-ошибок, доп. тесты на переходы статусов). Проект
готов к проведению занятия — из подготовки к живому созвону остаётся
только заранее поднять стенд (`docker compose up --build -d`) и
прогнать `docs/LESSON_PLAN.md` глазами ведущего.

## Важные ограничения, которые нельзя терять при реализации

- Занятие живое, 90 минут, плотный тайминг — не превращать реализацию в
  избыточно сложный продакшен-грейд сервис.
- ELK и весь стенд поднимаются **до** занятия, не во время него.
- Баги должны быть реалистичными и по-настоящему невидимыми для мокнутых
  юнит-тестов в CI — в этом весь педагогический смысл.
- Один общий стенд у ведущего (не у каждого студента свой docker-compose).
